## What is Openlysts?

Openlysts is an **autonomous intelligence engine** that continuously scans tens of thousands of open-source repositories, scores them by **velocity** (not vanity stars), and maps SaaS-to-open-source displacement signals — all through a live, interactive interface.

It's not a list. It's not a blog. It's a **living engine** that never sleeps.

<table>
<tr>
<td width="50%" valign="top">

**What it does:**
- 📡 Scans the entire open-source ecosystem in real-time
- ⚡ Scores by velocity — not popularity, not stars
- 💰 Maps paid SaaS tools to open-source alternatives
- 🔍 Fuzzy search across every repository, category, and language
- 📈 Tracks rising projects before they trend

</td>
<td width="50%" valign="top">

**What it doesn't do:**

- ❌ Curate "awesome lists" by opinion

## 🚀 Quick start

### Clone and run locally

```bash
# Clone the repository
git clone https://github.com/Openlyst/openlysts.git
cd openlysts

# Install dependencies
npm install

# Start development servers
npm run dev
```

The dev server starts both servers simultaneously:
- 🖥️ **Frontend** — [http://localhost:5173](http://localhost:5173) (Vite + React)
- ⚙️ **Backend** — [http://localhost:3001](http://localhost:3001) (Express + PostgreSQL)

### All commands

| Command | Description |
|:---|:---|
| `npm run dev` | Start development servers |
| `npm run build` | Production build |
| `npm start` | Run production server |
| `npm run lint` | Check code quality |
| `npm test` | Run test suites |

## How it works

The entire catalog lives in **RAM**. Your search resolves before you finish typing.

A background pipeline crawls GitHub, scores every repository against a hybrid formula, maps SaaS displacement signals, and keeps everything fresh — automatically.

```
Relevance = (TextScore × 1.5) + (AuthorityScore × 0.5)
          + (EngagementScore × 0.2) + log(Stars)
```

## 🔒 Security

| Protection | Implementation |
|:---|:---|
| **Authentication** | Session-based with `__Host-` cookies, bcrypt hashing |
| **Rate Limiting** | Login: 5 req/15min · Search: 30 req/min · API: 60 req/min |
| **Security Headers** | Helmet.js — CSP, HSTS, X-Frame-Options, X-Content-Type |

## FAQ

<details>
<summary><b>Is this just another awesome list?</b></summary>
<br/>
No. Awesome lists are curated by humans with opinions. Openlysts is scored by data — commit velocity, contributor growth, issue resolution rates, and trajectory. It's the difference between someone telling you a stock is "good" and seeing the earnings report.
</details>

<details>
<summary><b>How does the scoring work?</b></summary>
<br/>
The Velocity Score is a composite of six signals: commit frequency, contributor growth rate, issue close velocity, fork-to-star ratio, dependency adoption, and recency weight. It's designed to catch momentum before it becomes popularity.
</details>

<details>
<summary><b>Is this just a GitHub API wrapper?</b></summary>
<br/>
No. The GitHub API returns raw metadata. Openlysts scores it, categorizes it, maps alternatives, caches everything in memory, and presents it through an interface that loads in under 200ms. The API is the input, not the product.
</details>

<details>
<summary><b>How fresh is the data?</b></summary>
<br/>
The ingestion pipeline runs daily via Vercel Cron. In standalone mode, it runs every 10 minutes. The catalog is rebuilt from source on every boot.
</details>

<details>
<summary><b>What makes this different from GitHub Trending?</b></summary>
<br/>
GitHub Trending shows popularity. Openlysts shows trajectory. A project gaining 500 stars in a week when it started at 800 total is a fundamentally different signal than one gaining 500 when it started at 50,000.
</details>

<details>
<summary><b>Can I self-host this?</b></summary>
<br/>
Yes. Clone the repo, run npm install, npm run dev. The full catalog engine runs locally. The database is PostgreSQL — connect to your own instance and you're running your own intelligence platform.
</details>

<details>
<summary><b>How do I contribute?</b></summary>
<br/>
Fork the repo, create a feature branch, and submit a PR. We welcome contributions to the catalog data, scoring algorithm, and UI components.
</details>
