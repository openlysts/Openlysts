## What is Openlysts?

Openlysts is an **autonomous intelligence engine** that continuously indexes a **growing catalog of open-source repositories**, scores them by **velocity and momentum** (not vanity stars), and maps **SaaS-to-open-source displacement signals** — all through a live, sub-millisecond in-memory interface.

It's not a list. It's not a blog. It's a **living engine** that never sleeps.

<table>
<tr>
<td width="50%" valign="top">

**What it does:**
- 📡 Indexes a continuously growing curated catalog with in-memory inverted search (sub-millisecond latency)
- ⚡ Scores by velocity — commits, momentum, release frequency, issue resolution
- 💰 Maps paid SaaS tools to verified open-source alternatives
- 🔍 Sub-millisecond keyword, category, and multi-attribute discovery
- 📈 Tracks breakout projects before they hit mainstream aggregators

</td>

- ❌ Curate "awesome lists" by opinion

## How it works

The entire catalog lives in **RAM**. Your search resolves before you finish typing.

A background pipeline crawls GitHub, scores every repository against a hybrid formula, maps SaaS displacement signals, and keeps everything fresh — automatically.

```
Relevance = (TextScore × 1.5) + (AuthorityScore × 0.5)
          + (EngagementScore × 0.2) + log(Stars)
```

## FAQ

<details>
<summary><b>Is this just another awesome list?</b></summary>
<br/>
No. Awesome lists are curated by humans with opinions. Openlysts is scored by data — commit velocity, contributor growth, issue resolution rates, and trajectory. It's the difference between someone telling you a stock is "good" and seeing the earnings report.
</details>

<details>
<summary><b>How does the scoring work?</b></summary>
<br/>
The Velocity Score is a composite of six signals: commit frequency, contributor growth rate, issue close velocity, fork-to-star ratio, dependency adoption, and recency weight. It's designed to catch momentum before it becomes popularity.
</details>

<details>
<summary><b>Is this just a GitHub API wrapper?</b></summary>
<br/>
No. The GitHub API returns raw metadata. Openlysts scores it, categorizes it, maps alternatives, caches everything in memory, and presents it through an interface that loads in under 200ms. The API is the input, not the product.
</details>

<details>
<summary><b>How fresh is the data?</b></summary>
<br/>
The ingestion pipeline runs daily via Vercel Cron. In standalone mode, it runs every 10 minutes. The catalog is rebuilt from source on every boot.
</details>

<details>
<summary><b>What makes this different from GitHub Trending?</b></summary>
<br/>
GitHub Trending shows popularity. Openlysts shows trajectory. A small project gaining hundreds of stars in a week is a fundamentally different signal than a giant project gaining the same.
</details>

<details>
<summary><b>Can I self-host this?</b></summary>
<br/>
Yes — see the [Run locally (for developers)](#%EF%B8%8F-run-locally-for-developers) section. The catalog engine and core search run locally with no external setup; account features use PostgreSQL, so point `DATABASE_URL` at your own instance for the full experience.
</details>

<details>
<summary><b>How do I contribute?</b></summary>
<br/>
Fork the repo, create a feature branch, and submit a PR. We welcome contributions to the catalog data, scoring algorithm, and UI components.
</details>

## 🧑💻 Run locally (for developers)

Openlysts is **hosted and free to use**, so most people never need to install anything. If you're a developer who wants to explore the code, contribute, or run your own instance:

```bash
# Clone the repository
git clone https://github.com/openlysts/Openlysts.git
cd Openlysts

# Install dependencies
npm install

# Start development servers (frontend + backend together)
npm run dev
```

- 🖥️ **Frontend** — http://localhost:5173 (Vite + React)
- ⚙️ **Backend** — http://localhost:3001 (Express + in-memory catalog engine)

| Command | Description |
|:---|:---|
| `npm run dev` | Start development servers |
| `npm run build` | Production bundle build (Vite) |
| `npm start` | Run production Express server |
| `npm run lint` | Run ESLint across codebase |
| `npm run typecheck` | Run TypeScript checks |
| `npm test` | Run core services & invariant tests |
| `npm run test:api` | Run API integration tests |

> **Note on self-hosting:** the discovery catalog and core search run entirely in memory and need no external setup. Account features (sign-in, bookmarks sync, voting) use PostgreSQL — point `DATABASE_URL` at your own instance when you need them.

## ❓ Troubleshooting

**1. "Alternatives / Discover looks empty or shows only a small fallback list."**

Open the browser console (F12). If you see `500 ... queryAlternatives` or a CORS error, the frontend and API disagree about where the API lives:
- In local development, open the app via the same origin the API allows (e.g. `http://localhost:5173`, not a raw LAN IP on very old builds — newer builds allow LAN/private origins).
- Verify the backend is running and healthy: open `http://localhost:3001/api/health` — you should see `{"status":"ok",...}`.
- On the hosted site, a 503 / "deployment paused" page means the Vercel deployment was paused — resume it from the Vercel dashboard.

**2. Testing on your phone from your PC ("PC IP and port").**

- Make sure the phone is on the **same Wi-Fi network** as the PC (not mobile data).
- Find your PC's IPv4 address: run `ipconfig` (Windows) and look under the active Wi-Fi/Ethernet adapter (e.g. `192.168.1.x`).
- Start the dev servers, then open `http://<PC-IP>:5173` in the phone browser — **not** `localhost` (on the phone, `localhost` means the phone itself).
- If nothing loads at all, Windows Firewall is likely blocking Node.js inbound connections — allow `node.exe` on private networks (Windows Security → Firewall & network protection → Allow an app), or temporarily allow port `5173`/`3001`.
- If the page loads but data calls fail, double-check both servers are up (`/api/health` above) and that you're on the latest code (older builds rejected LAN origins with a CORS 500).

**3. Installed app (PWA) shows old content or a blank screen.**

- Close the app fully and reopen it.
- If it still shows stale content, clear the site's data (browser → site settings → clear storage) or uninstall and re-install the app.
- PWA/service workers require HTTPS — the hosted app at `https://openlysts.dpdns.org` is correct; `localhost` is the only exception browsers allow for testing.

**4. I registered but can't sign in.**

- Confirm your email address was verified (check the verification link, including spam/junk folders).
- Complete the Cloudflare security check on the sign-in form — the button stays disabled until it passes.
- If you see a rate-limit message, wait a few minutes and retry (limits protect the free service).

**5. Something else is broken.**

- Open the browser console and copy any red errors, then open a GitHub Issue with them — include the page URL and what you clicked. Every report is read and acted on.
