# Openlyst QA Tester

## Overview
This skill instructs the agent on how to correctly and efficiently run the Playwright End-to-End Golden Path test for Openlyst. The test covers all major routes, global search, bookmarking (localStorage), categorization, AgentPM (Admin) navigation, Settings, and API health, all in a single efficient flow.

## Dependencies
Requires the Playwright test runner and the `tests/e2e.spec.js` test file to be present in the repository.

## Quick Start
Run the test suite using `npx playwright test`. Ensure that a dev server is either running or `playwright.config.js` is configured to start it.

**Note on Real Browser Automation:**
Playwright performs *real* browser automation. It spins up an actual browser instance (Chromium/Webkit/Firefox) and simulates genuine user interactions like clicks, typing, and navigation at exact pixel coordinates. 

By default, tests run in **headless mode** (invisible background process) for speed. 
- To watch the test execute visually in a real browser window, run: `npx playwright test --headed`
- To run with an interactive UI dashboard (great for debugging), run: `npx playwright test --ui`

## Workflow

### 1. Preparation
- If the user specifically asks to test with a clean database state, first run `npm run db:reset` and `npm run db:seed`. Otherwise, standard tests can be run safely against existing data.
- Ensure that the `.env.local` file contains necessary variables for the backend to start up correctly if the dev server isn't already running.

### 2. Execution
- Execute the command `npx playwright test` in the `openlyst` repository root.
- The test `e2e.spec.js` will start the application, navigate through the UI, interact with components, and verify API responses.

### 3. Failure Handling
- If a test fails due to a timeout waiting for an element, do not assume the test is fundamentally broken immediately. Re-check the Openlyst DOM structure as the UI may have evolved (e.g. relying on `.card` instead of text, or specific component structures).
- Look at the `test-results/` directory generated by Playwright for error context or stack traces.
- Attempt to auto-fix the component or locator in `e2e.spec.js` if it's merely a test desync.

## Common Mistakes
- Running fragmented tests concurrently which triggers multiple Vite restarts and times out. Always stick to the unified Golden Path `e2e.spec.js`.
- Modifying React code indiscriminately on a test failure before determining if it's just an outdated Playwright locator.
